### 1.3 光照：本轮真正解决的两件事
1. **太阳必须用 shadow linking 关进室内**。外壳会把平行光整个吃掉；而面光放在窗后 0.3 m
   只会变成泛光灯，永远没有锐边光柱。`_sun_linked()` 用 Blender 5.2 的
   `light.light_linking`：`receiver_collection` = 我的全部几何 + 雾，`blocker_collection` = 我的
   全部几何里**除玻璃**（`_gl` / `_bk` / `_gc`）。于是外壳既不吃我的太阳、也不被我照亮，
   太阳只从我 0.95 m 厚的真实窗洞进来 —— 光柱的形状**就是窗的形状**。
   日志实测：`sun 700 linked: 5501 receivers, 4056 blockers`。
2. **除太阳外所有灯关闭体积散射**（`ob.visible_volume_scatter = False`）。43 盏补光都参与散射时，
   整个空间会被均匀点亮成雾箱（这就是之前"牛奶感 + 噪点"的根因）；现在只有太阳散射，
   阴影干净、雾只在光路上发亮。
3. `hd_atmosphere.haze()` 局部体积：`density=0.0055, height=42, extent=210, aniso=0.35`。
   低密度 + 高度衰减，室内 40 m 视线 τ≈0.22，看得见"空气"，但不会糊。
4. 试过第三种做法（**代码保留但默认关闭**）：给每束光单独做一根沿光束方向的**体积楔**
   （闭合管 + Principled Volume，密度随距离衰减），代替"灰尘"把侧视光柱提亮。
   实验结论是**不可用**：密度 0.16 / 0.24 看不见，0.55 反而变成一块暗褐色遮挡；
   顶点色 `fade` 属性在 5.2 的 Volume 里读不到，长度衰减失效。
   所以 `SHAFTS_ON = False`（模块默认），光柱交给上面 1–3 条的物理方案。
   导出到游戏引擎时也应该关（引擎里用后处理体积光 / 光柱贴片）。

## 2. 确切 API

```python
build(K=None, MAT=None, origin=(0.0, 0.0), rot=0.0, scale=1.0, seed=5) -> [bpy.types.Object]
interior_lights(spec="full", air=True, sun=True) -> [bpy.types.Object]   # 灯光，不含网格
atmosphere(scene=None, density=0.0055, height=42.0, extent=210.0, aniso=0.35, preset="fog")
footprint() -> (68.50, 83.75)     # (宽 x, 纵深 y)，米
height()    -> 28.35              # 采光塔顶
CAMS        -> [(name, loc, look, lens), ...]
preview(samples=24, res=(960, 540), only=None) -> [png paths]
```

- `origin` 是 **church frame 原点 = 交叉部中心投影**，不是 footprint 中心。
- 几何一律按 scale=1 的真实尺寸建模、地板 z=0、对象变换为单位阵，最后一次性乘
  `T(origin) @ Rz(rot) @ S(scale)`（外加 `Z_LIFT=1.10` 抬到外壳楼板上）。
- `build()` **只返回网格**；灯光要另外调 `interior_lights()`（它会把同一套变换应用到灯上，
  所以必须在 `build()` 之后立刻调用）。
- 需要的 `MAT` 键：随便传 `None`（自带 32 项材质）。若传外部材质表，同名键会覆盖。

## 5. 剩余问题（诚实）

1. **体积光只在"暗背景 + 顺着光束看"时可读**。这是物理，不是参数问题：光束的单次散射辐亮度
   只有被日照墙面反射亮度的 1/5–1/10，侧视时几乎看不见；把雾加上去只会让全屋变成牛奶
   （密度 0.022 的那一轮就是这么糊掉的）。正确的读法是低密度雾 + 一束光穿过明暗对比强的空间，
   或者干脆让相机接近光束方向。真正的"可见光柱"在游戏里应该用后处理体积光/光柱贴片做。
2. 拱顶腹面（大面积）读起来偏素，肋的断面在 480 宽下偏细；再往上加就是雕花级别的成本。
3. 长椅/唱诗席仍是简化几何（`_bx` 盒子 + 三叶饰），近景看得出是程序化的。
4. 彩玻在掠射角下仍会偏灰（Principled + alpha 的固有问题），需要真正的透射 BSDF 才能完全解决。
5. 后殿半穹顶从唱诗席机位看不太出来（机位太低、被 reredos 挡住）。

## 6. 需要主 AI 插的代码（逐字）

`capital.py` 里已经有一行 `out = hd_glue().cathedral(hd_mat(), rng, cx, cy, math.pi, 0.0)`。
**外壳那一路不要动。**室内这一路在 `capital.py` 的教堂分支里、外壳 `out` 之后加：

```python
        import hd_cathedral_int as CI
        parts = CI.build(None, hd_mat(), origin=CATH_C, rot=0.0, scale=1.0, seed=5)
        out = list(out) + list(parts)
        lights = CI.interior_lights()        # 必须在 build() 之后调用（沿用同一套变换）
        out = list(out) + list(lights)
```

要点（**rot 必须是 0.0，不是 math.pi**）：

- `CATH_C = (-224.96, 85.84)`，`CATH_C = (-152*CITY_SCALE, 58*CITY_SCALE)`，`CITY_SCALE = 1.48`。
- 外壳自己是以 `rot=math.pi` 摆的（它的局部 +Y 是西立面），所以它的后殿落在城市 **+Y**；
  我的 church frame 的 +Y 也是后殿，因此我也 `rot=0.0`。两边交叉部都恰好落在
  `CATH_C + (0, +7.5)`，**实测重合**。用 `math.pi` 会把后殿甩到西边，是错的。
- `scale=1.0`（`capital_hd_glue.place()` 对教堂没有做 `CITY_SCALE` 缩放，别自己乘 1.48）。
- 室内自带 `Z_LIFT=1.10`，正好落在 `Z_FLOOR` 上，**不要再抬**。
- 灯光是单独返回的：如果不想在城里带 43 盏灯，`CI.interior_lights(spec="none")` 或干脆不调；
  但那样室内会全黑（室内没有天光）。
- 如果最终场景里要保留其他太阳：我这盏 `ci_sun` 是 light-linking 的，外壳不吃它、它也不照亮
  外壳，两者不冲突；但**不要再给室内加第二个太阳**，否则亮度翻倍。
- 导出到游戏引擎时可以把 `CI.SHAFTS_ON = False` 再 build（体积楔是给 Cycles 看图的，
  引擎里应该用后处理体积光）。
